## 🎯 Module Objective

The goal of this module was to build an automated setup and deployment pipeline for the Streetcode web application using **Ansible** and **Docker Compose**, replacing manual configuration with an **Infrastructure as Code (IaC)** approach.

---

## 🏗 Implemented Architecture & Services

The application was containerized into three connected services running in a shared Docker bridge network:

| Service | Container Name | Technology / Image | Host Port | Container Port | Description |
| :--- | :--- | :--- | :---: | :---: | :--- |
| **Database** | `streetcode-db` | `mcr.microsoft.com/mssql/server:2022-latest` | `1433` | `1433` | MS SQL Server storing core application data. |
| **Backend** | `streetcode-backend` | Custom image `streetcode-app-backend` (.NET 6) | `5000` | `5000` | ASP.NET Core Web API with business logic and EF Core migrations. |
| **Frontend** | `streetcode-frontend` | Custom image `streetcode-app-frontend` (React + Nginx) | `3000` | `80` | Client application served statically via Nginx. |

---

## 📋 Tasks Completed

### 1. Docker Containerization & Orchestration

- Developed multi-stage Dockerfiles for the Backend (.NET 6 SDK/Runtime) and the Frontend (Node 16 / Nginx).
- Created a unified `docker-compose.yml` with health checks, a bridge network, persistent volumes, and environment variable support via `.env`.

### 2. Ansible Playbook & Modular Roles

Designed modular Ansible roles to fully automate server provisioning:

| Role | Responsibilities |
| :--- | :--- |
| **`common`** | APT cache update, base dependencies, passwordless `sudo` via `/etc/sudoers.d/ansible_nopasswd`. |
| **`docker`** | Official Docker GPG key (`/etc/apt/keyrings/docker.gpg`), repository setup, installation of Docker Engine and the Compose plugin. |
| **`streetcode_app`** | Git clone, `.env` generation, teardown of old containers, image build, and stack startup. |

## 🛠 Issues Resolved During Implementation

### 1. APT repository & lock errors

- **Issue:** `Failed to update apt cache` during playbook execution.
- **Solution:** Removed the stale `/var/lib/dpkg/lock-frontend` lock, deleted deprecated third-party PPA entries (e.g., Jenkins keyring errors), and refreshed package lists.

### 2. Docker keyring & repository conflicts

- **Issue:** `Conflicting values set for option Signed-By` caused by duplicate Docker sources.
- **Solution:** Removed duplicates in `/etc/apt/sources.list` and `/etc/apt/sources.list.d/`, re-imported the official GPG key into `/etc/apt/keyrings/docker.gpg`, and recreated a single clean `docker.list`.

### 3. Port conflicts with legacy containers

- **Issue:** The playbook finished with `failed=1` after building images.
- **Solution:** Found old containers occupying host ports `1433`, `5000`, and `3000`, stopped and removed them, then re-ran the playbook so the new containers could bind cleanly.

### 4. Backend startup delay

- **Issue:** Swagger (`http://localhost:5000/swagger`) was unreachable while the Frontend was already up.
- **Solution:** Checked `docker logs streetcode-backend` and confirmed the delay came from initial EF Core migrations and Hangfire setup. The endpoints became available once database initialization completed.
