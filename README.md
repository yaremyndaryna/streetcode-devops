# Streetcode DevOps

This branch contains everything needed to deploy **Streetcode** on AWS from scratch: infrastructure (Terraform), server configuration (Ansible), CI (GitHub Actions) and CD (Jenkins) on a K3s cluster.

---

## What you will get

Two EC2 instances:

| Node | Runs | Exposed ports |
| --- | --- | --- |
| **App Node** (medium) | K3s with Frontend (2 replicas), Backend (.NET 6 API + Swagger), MS SQL Server, Redis, Node Exporter | `80`, `443` |
| **Tools Node** (small) | Jenkins, Prometheus, Grafana, Node Exporter, cAdvisor | `8080` (Jenkins), `9090` (Prometheus), `3000` (Grafana) |

Database, cache and internal service ports (`1433`, `6379`, `5000`) are **not** exposed to the internet. Ports `6443` (Kubernetes API) and `9100` (Node Exporter) are reachable only between the two nodes.

**Flow:** push to `cloud` → GitHub Actions builds, scans and pushes images to GHCR → Jenkins verifies the checks, runs tests, deploys to K3s, runs smoke tests and promotes `:latest`.

---

## Before you start

You need:

- [ ] An **AWS account** with permission to create EC2 instances and Security Groups, and AWS credentials configured locally
- [ ] An **EC2 key pair** (and the private key on your machine, e.g. `~/.ssh/id_rsa`)
- [ ] **Terraform** and **Ansible** installed locally
- [ ] A **GitHub Personal Access Token (PAT)** with repository and package write scopes
- [ ] **GitHub repository secrets** (Settings → Secrets and variables → Actions):
  - `SONAR_TOKEN` (SonarCloud)
  - `SNYK_TOKEN` (Snyk)

> **Using your own fork?** Several files contain the original owner's names. Replace them with yours before the first run:
> - `Jenkinsfile`: `IMAGE_BACKEND`, `IMAGE_FRONTEND` and the repository path in the GitHub API call
> - GitHub workflows: `IMAGE_BACKEND`, `IMAGE_FRONTEND`, and the SonarCloud project key / organization
> - `k8s/app/` manifests: image references, if they are set there

## Step 1: Provision infrastructure (Terraform)

```bash
cd terraform
cp terraform.tfvars.example terraform.tfvars
```

Edit `terraform.tfvars` and fill in your values (AMI ID, instance types, key pair name), then:

```bash
terraform init
terraform apply
```

When it finishes, **write down the public IP addresses** of the App Node and the Tools Node from the output.

---

## Step 2: Configure the servers (Ansible)

```bash
cd ../ansible
```

1. Put the IP addresses from Step 1 into `inventory.ini`.
2. Create your secrets file from the template and fill it in:

   ```bash
   cp group_vars/all/secrets.example.yml group_vars/all/secrets.yml
   ```

3. Run the playbook:

   ```bash
   ansible-playbook -i inventory.ini setup-infrastructure.yml
   ```

This installs and configures Docker, K3s, Jenkins, Prometheus, Grafana, Node Exporter and cAdvisor on the right nodes.

> `terraform.tfvars` and `secrets.yml` contain sensitive data. They must be in `.gitignore`; never commit them.

## Step 3: Set up Jenkins

### 3.1 Unlock Jenkins

Get the initial admin password from the Jenkins container on the Tools Node:

```bash
ssh -i ~/.ssh/id_rsa ubuntu@<TOOLS_NODE_PUBLIC_IP> \
  "sudo docker exec streetcode-jenkins cat /var/jenkins_home/secrets/initialAdminPassword"
```

Then open `http://<TOOLS_NODE_PUBLIC_IP>:8080`, paste the password, install the suggested plugins and create your admin account.

### 3.2 Add credentials

Go to **Dashboard → Manage Jenkins → Credentials → System → Global credentials (unrestricted)** and add these **4** credentials. The IDs must match exactly:

| ID | Type | Value |
| --- | --- | --- |
| `k3s-kubeconfig` | Secret file | `kubeconfig` from the App Node (`/etc/rancher/k3s/k3s.yaml` or the one generated by Ansible) |
| `github-credentials` | Username with password | Your GitHub username + PAT |
| `app-node-ip` | Secret text | Public IP of the App Node |
| `tools-node-ip` | Secret text | Public IP of the Tools Node |

> If you use `/etc/rancher/k3s/k3s.yaml`, make sure the `server:` address in it points to the App Node's public IP, not `127.0.0.1`.

### 3.3 Create the pipeline

1. On the dashboard click **New Item**, enter `streetcode-pipeline`, choose **Pipeline**, click **OK**.
2. In the **Pipeline** section set:
   - **Definition:** `Pipeline script from SCM`
   - **SCM:** `Git`
   - **Repository URL:** `https://github.com/<your-org>/<your-repo>.git`
   - **Credentials:** `github-credentials`
   - **Branch Specifier:** `*/cloud`
   - **Script Path:** `Jenkinsfile`
3. Click **Save**.

## Step 4: Run the pipeline

Push a commit to the `cloud` branch (this triggers both GitHub workflows), then in Jenkins click **Build Now** on `streetcode-pipeline`.

**GitHub Actions** (two independent workflows):

| Workflow | Job (required check) | What it does |
| --- | --- | --- |
| SonarCloud Code Analysis & Snyk Security | `Build, Analyze & Security Scan` | SonarCloud analysis, Snyk dependency scan |
| Build, Push & Scan Images | `Build, Push & Trivy Scan` | Builds backend and frontend images, pushes them to GHCR with the commit SHA tag, scans them with Trivy |

**Jenkins pipeline** stages:

1. **Check GitHub Security & Build Status**: waits until both required checks above succeed on this commit
2. **Backend Unit Tests** (`dotnet test`)
3. **Frontend Unit Tests** (`npm test`)
4. **Verify Images in GHCR**: confirms the images for this commit exist
5. **Deploy to K3s**: applies `k8s/app/` and sets the new images
6. **Verify Rollout Status**
7. **Smoke Test**: checks the frontend and `/swagger/index.html`
8. **Verify Prometheus Scraping**: warning only
9. **Promote `:latest`**

If anything fails **after** deployment, Jenkins automatically rolls back backend and frontend (`kubectl rollout undo`).

> Jenkins waits for the GitHub checks to finish, so the first build can take a while. Check the **Actions** tab if it seems stuck.

## Security notes

- `8080`, `3000` and `9090` are open to `0.0.0.0/0` by default for convenience. **For anything beyond testing, restrict them to your own CIDR or put them behind a VPN, and enable HTTPS.**
- Never commit `terraform.tfvars`, `.env` or `ansible/group_vars/all/secrets.yml`.
- Secrets live in three layers: local files (not committed), GitHub Secrets (for Actions), Jenkins Credentials (for deployment).
- Trivy and Snyk currently report findings without failing the build; make them blocking for production.
